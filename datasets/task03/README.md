# Задача 03: синтетический кандидат 20 + 20

Версия `task03.candidate.v1`, 9 октября 2026. Все 40 диалогов и gold созданы ассистентом;
не содержат импортированных IMCS21-текстов и не прошли независимую человеческую/клиническую проверку.
Это материал для работы Дениса и Павла, а не окончательно согласованный тест.

- `development.json`: 20 случаев для проверки правил и интерфейса.
- `heldout_candidate.json`: 20 случаев, резерв для итогового теста. Модель на них не запускалась;
  не использовать для выбора модели/промпта. До двух разметок и арбитража финальное замораживание открыто.
- `manifest.json`: версия, число случаев, SHA256 каждого сплита.
- `sources.json`: происхождение, версия, условия; внешний IMCS21 только как кандидат.
- `disputed-cases.json`: 9 групп вопросов на согласование и одна зафиксированная редакция синтетического текста.
- `blind/`: пустые формы A/B по утилите Дениса, без gold; имена разметчиков не заполнены.
- `build.py`: воспроизводимый источник вымышленных диалогов и предложенных эталонов.

Идентификатор исходной записи `source_record_id` и `dialogue_group_id` сохраняются при изменениях.
Новый вариант одного разговора обязан получить тот же group ID и тот же split. Проверка выявляет
пересечения ID/group/буквального транскрипта и совпадения со старыми экспериментами; смысловую близость
и правильность групп дополнительно проверяют люди. Менять зафиксированный JSON без новой версии нельзя.

Во всех шести полях записаны status/value/evidence. Дословные цитаты берутся только у пациента;
unknown остаётся без доказательств. Есть отрицания, неуверенность, исправления, противоречия, сведения
родственника, планы принять препарат, несколько препаратов и неоднозначные дозы.

## Что выполнить людям

1. Денис проверяет китайский текст и условия источников, Павел берёт минимум `task03_11`–`task03_20`.
2. Независимо заполнить A/B; имена не заполнять до фактического чтения человеком. Для независимости
   сначала читать только формы `blind`, а не предложенный gold или автоматический отчёт.
3. Сравнить утилитой Дениса, обсудить расхождения и записать арбитра/причину. Связать случаи с 04 и 08
   после появления реальных аудиопримеров и UI; их идентификаторы пока не придуманы.
4. Утвердить новую версию и контрольные суммы; отчёты предыдущих версий сохранять отдельно.

```sh
.venv/bin/python tools/task03_check.py
.venv/bin/python tools/annotation_review.py compare \
  --source datasets/task03/development.json \
  --first local_annotations/review_A.json --second local_annotations/review_B.json \
  --output local_annotations/differences.json
```

Для второй команды сначала скопировать нужную пару из `blind` в `local_annotations`, затем заполнить её.
Для резерва заменить source на `heldout_candidate.json`. Пустые формы намеренно не проходят compare.

`task03_check.py` проверяет формат 40 записей и проводит создание/чтение/редактирование 10 development
случаев через настоящий API с фикстурным extractor. Это проверка совместимости, без Ollama, без оценки
качества генерации, без имитации человека. Отчёт: `docs/task03-check-report.json`.

Учебные три примера baseline, старые 40 случаев сравнения моделей и тест 30 случаев от 6 октября
остаются отдельно: они уже использовались в экспериментах и не являются этим новым резервом.
