# Бэкенд Qwen3.5: первый рабочий контур

Это локальный прототип извлечения **шести фактов**, а не полный SOAP, диагнозы или назначения.
Интерфейсные названия полей и инструкции модели — китайские. Объяснения разработчику — русские.

## Запуск

Из корня репозитория:

```sh
cd /Users/pavel/Documents/github/smartmed-copilot
.venv/bin/pip install -e '.[dev]'
ollama list
.venv/bin/uvicorn smartmed.api:create_app --factory --host 127.0.0.1 --port 8000
```

Модель `qwen3.5:4b` уже скачана. Ollama должен работать. Если Ollama не запущен,
открой приложение Ollama или запусти `ollama serve` в отдельном терминале.
Если он уже работает, второй сервер Ollama запускать не нужно.

Открой http://127.0.0.1:8000/docs — интерактивную документацию FastAPI (Swagger).
Она позволяет отправлять запросы без написания фронтенда. `GET /health` проверяет наличие
Ollama и точного тега модели; успешный health не является проверкой качества генерации.

Первый запрос с подготовленным китайским диалогом:

```sh
curl --fail-with-body http://127.0.0.1:8000/v1/drafts \
  -H 'Content-Type: application/json' \
  --data-binary @examples/encounter_zh.json
```

В ответе `document` содержит факты, `id` — идентификатор сохранённого черновика,
`version` — его версию, `model_metadata` — модель, digest, инструкцию, число попыток и время.
Повторный POST создаёт новый черновик: идемпотентность пока не реализована.

## Что происходит в запросе

1. FastAPI проверяет вход: роли `doctor/patient`, уникальные числовые `turn_id`,
   непустой текст, максимум 40 реплик и 2000 символов суммарно. Длинный диалог отклоняется,
   не обрезается молча. Это граница первого прототипа, не поддержка полного длинного приёма.
2. Pydantic описывает обязательные шесть полей и три отдельные формы факта: present,
   negated, unknown. Для каждой формы ограничения значения и массива цитат включены
   в саму JSON-схему (`anyOf`, `const`, `minItems/maxItems`), а не только Python-валидаторы.
   Лишние поля и неправильные типы запрещены. Выполнение ограничений всё равно проверяется
   после генерации: поддержка JSON-схемы движком не заменяет серверную проверку.
3. Instructor формирует JSON-схему и валидирует результат. Наш адаптер вызывает
   **нативный локальный `/api/chat` Ollama** с `format=<schema>`, `think=false`,
   `temperature=0`, `seed=42`. Типы из OpenAI SDK используются только в памяти для
   совместимости с Instructor: внешнего OpenAI-клиента или запроса здесь нет.
4. Адаптер сужает цитаты в JSON-схеме до неизменяемых реплик пациента и их фрагментов,
   выделенных по знакам препинания. Для каждого фрагмента задаётся точный turn_id.
   Модель выбирает цитату из списка, а не переписывает её свободно. Значение всё ещё
   генерируется моделью; валидатор требует буквальный фрагмент цитаты.
   Дополнительно сервер повторно сверяет цитату с оригиналом и проверяет правила статусов,
   значение кашля, основание отрицания аллергии и основание отрицания приёма лекарств.
5. Если ответ ошибочный, Instructor отправляет модели ошибки валидатора и позволяет
   **один повтор**. Ответ снова проходит весь набор проверок. Значения не очищаются и
   не заменяются на `unknown` автоматически, чтобы не скрывать ошибки.
6. Успешный ответ сохраняется в SQLite со статусом `requires_review`. Плохой ответ
   после повторной попытки даёт HTTP 502, без сохранения успешного черновика.
7. Редактирование повторяет те же проверки; подтверждение и экспорт — отдельные операции.

**JSON-схема ограничивает форму ответа. Она не доказывает правильность медицинского смысла.**
Instructor — библиотека обработки структурированного ответа и повторных попыток, не новая модель
и не обучение весов. Этот запуск не делает fine-tuning.

## Контракт для Дена и формы

`GET /v1/form` возвращает версию контракта, китайские подписи и JSON-схему.
Фронтенд может построить шесть строк с переключателем статуса, значением и исходной цитатой.
Это API для формы, не готовый визуальный интерфейс врача.

Шесть полей: `发热`, `咳嗽`, `症状持续时间`, `青霉素过敏`, `已用药物`, `已用药物剂量`.

```json
{
  "status": "present",
  "value": "咳嗽",
  "evidence": [{"turn_id": 2, "quote": "咳嗽两天"}]
}
```

| Статус | Значение | Цитата |
|---|---|---|
| `present` — явно есть | Непустой фрагмент оригинала | Обязательна |
| `negated` — явно отрицается | `null` | Обязательна, включая отрицание |
| `unknown` — неизвестно | `null` | `[]` согласно текущему контракту |

Требование пустой цитаты у `unknown` — наш выбор контракта. Само по себе цитирование слов
«не знаю» не делает модель семантически неверной. Для объяснения неизвестного значения
фронтенд может показывать исходный диалог; отдельное поле причины пока не добавлено.

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Проверить локальный сервер и тег |
| `GET /v1/form` | Контракт формы |
| `POST /v1/drafts` | Стенограмма → генерация → сохранение |
| `GET /v1/drafts/{id}` | Прочитать черновик |
| `PUT /v1/drafts/{id}` | Заменить все шесть полей после редактирования |
| `POST /v1/drafts/{id}/confirm` | Подтвердить текущую версию |
| `GET /v1/drafts/{id}/history` | История генерации, правок и подтверждений |
| `GET /v1/drafts/{id}/export` | Получить JSON подтверждённого черновика |

PUT принимает `expected_version`, `actor`, `document`. В `document` передаются все шесть полей.
Подтверждение принимает:

```json
{"expected_version": 1, "reviewer": "demo-reviewer", "reviewed": true}
```

Если версия устарела, сервер отвечает **409**: нужно заново загрузить черновик.
Редактирование подтверждённого черновика сбрасывает подтверждение; экспорт опять блокируется.
Поля reviewer/actor сейчас задаёт клиент — это журнал рабочего процесса, не удостоверенная
личность и не юридическая подпись. История содержит полные снимки каждой версии.
Ручная правка должна подтверждаться исходной стенограммой. Новые сведения требуют нового
диалога/черновика; ввод фактов без цитат в этом контракте запрещён.

HTTP 422 — плохой вход или ручная правка; 502 — невалидная генерация; 503 — модель отсутствует,
Ollama недоступен или занят другим запросом; 504 — превышен общий бюджет времени.
Один запрос занимает локальную модель; скрытой очереди нет. После 503 не запускай много
повторов одновременно. После таймаута Ollama может ещё освобождать вычислительные ресурсы.

## Настройки и ограничения

Настройки сервиса находятся в `src/smartmed/backend_settings.py`.
Они отделены от старой конфигурации планируемого MLX/full-SOAP контура.
Переменные имеют префикс `SMARTMED_BACKEND_`, например:

```sh
SMARTMED_BACKEND_MODEL=qwen3.5:4b \
SMARTMED_BACKEND_TIMEOUT_S=90 \
.venv/bin/uvicorn smartmed.api:create_app --factory --host 127.0.0.1 --port 8000
```

По умолчанию: контекст **8192**, выход **1600** токенов, 90 секунд на генерацию вместе
с повторами, один повтор. Контекст и инструкция отличаются от вчерашнего бенчмарка
(4096/1400), поэтому его задержки нельзя выдавать за задержки этого сервиса.
Адрес модели разрешён только на loopback; HTTP-редиректы и прокси из окружения отключены.
Файл `.env` автоматически не загружается, API-ключ не нужен.

SQLite: `data/smartmed.sqlite3`, исключён из Git. Стенограммы и история сохраняются
локально в открытом виде. Этот контур рассчитан на локальные синтетические демонстрации:
авторизация пользователей, шифрование хранилища, политика хранения и больничная интеграция
пока не реализованы. Запускать сервер следует на `127.0.0.1`.

Полный SOAP, ASR, ICD-кодирование и проверка назначений в этих эндпоинтах не реализованы.
Валидатор не устанавливает диагноз, не проверяет все медицинские утверждения, не гарантирует
полноту извлечения. У проверки отрицания аллергии узкий словарь: часть корректных формулировок
она отклонит. Короткое «нет» после вопроса врача тоже будет отклонено для этого поля;
поддержку доказательства из пары вопрос–ответ надо добавить отдельным проверяемым контрактом.
Для остальных полей смысл цитаты, принадлежность родственнику и противоречия пока в основном
зависят от модели и ручной проверки. Даже прошедшая проверки цитата может подтверждать не тот факт.

Проверка отрицания лекарств также консервативна: требует явной фразы о непринятии лекарства.
Необычная формулировка может вызвать отказ. Серверные проверки не превращают неизвестное
значение в отрицательное и не запрещают модели пропустить факт, поставив unknown — полноту
извлечения нужно оценивать отдельно. Для прототипа используем один процесс Uvicorn;
блокировка занятости внутри процесса, а не общая очередь для нескольких серверов.

## Проверки

```sh
.venv/bin/pytest
.venv/bin/python experiments/03_backend_smoke/run.py
```

Второй запуск реально обращается к локальной Qwen3.5, использует пять проблемных диалогов
из старого набора и проверяет сохранение/подтверждение/экспорт. Это регрессия известных случаев,
не независимый новый бенчмарк и не клиническое подтверждение качества. Артефакты в
`experiments/03_backend_smoke/results/` исключены из Git.

Первый завершённый прогон на инструкции v2: `results/20261005T023718Z/report.json` в папке эксперимента.
Пять запросов дали HTTP 201; два потребовали повторной генерации. В 30/30 полях статус
совпал со старым эталоном. В четырёх диалогах совпали также точные значения; в пятом
модель дала `我咳嗽` («я кашляю») вместо `咳嗽` («кашель»). Это отличие границы фрагмента,
а не изменение факта. До подтверждения экспорт давал 409, после — 200.
Полное время отдельных запросов: 11,678 / 12,425 / 7,607 / 12,534 / 5,920 секунды.
Подтверждение в smoke-тесте автоматическое на синтетике, не проверка врачом.

Итоговый повтор на инструкции **v6** с ограниченным выбором исходных цитат:
`results/20261005T025000Z/report.json`. Все 5 ответов дали HTTP 201; статусы и значения
совпали с эталонами во всех 30 полях. Время: 8,898 / 6,022 / 7,533 / 5,877 / 5,802 секунды.
Исходники, инструкция и схема сохранены рядом с результатом. Это небольшая регрессионная
выборка, использованная при разработке; общий прирост качества на независимых данных не измерен.

Промежуточные варианты тоже сохранены. В v3 был пропуск отрицания приёма лекарств,
а в v4/v5 модель ошибочно отрицала приём лекарств в диалогах, где он не обсуждался,
ссылаясь на настоящие, но нерелевантные цитаты. Это показало, почему формат и буквальность
недостаточны: после этого добавлено требование явного основания отрицания приёма лекарств.

Составной пример `examples/encounter_zh.json` также проверен через живой HTTP-сервер:
HTTP 201, инструкция v6, одна попытка, 10,461 секунды. Результат сохранён локально в
`data/demo_response.json`; в нём кашель, длительность, отрицание температуры, неизвестная
аллергия, ибупрофен и доза `200毫克` с буквальными цитатами. Черновик оставлен
`requires_review`, без автоматического подтверждения.

Разбор причин исходных ошибок: `docs/MODEL_FAILURES_RU.md`.
