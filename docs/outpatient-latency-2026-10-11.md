# Замеры генерации 11.10.2026

Новый режим включён по умолчанию: Qwen 3.5 4B → компактный выбор исходных фрагментов → дополнительный проход по решениям врача → сборка прежнего outpatient.v1 кодом. Сайт и печать используют прежний публичный контракт.

## Диалог

[Синтетический разговор](../examples/outpatient_realistic_synthetic_zh.json): 32 реплики, 1076 китайских символов, 71 исходный фрагмент. Разговорные уточнения, предполагаемая кровь в мокроте, забытые названия/дозы лекарств, родственник со своей астмой, противоречивая история аллергии, отсутствующий отчёт анализа, осмотр, предварительный диагноз, решения об обследовании/инфузии и предупреждения. Это авторский пример, не запись из больницы, не IMCS21 и не клинически подтверждённый случай.

## Результаты на одном компьютере

| Вариант | Секунды | Выходные токены, сумма проходов | Проверки примера |
|---|---:|---:|---|
| Полный JSON, Qwen 3.5 4B | 193.9 | 4096 | оборванный JSON, не принят |
| Компактный + проход плана, Qwen 3.5 4B, модель выгружена | 25.1 | 317 | 24/24 |
| Тот же вариант, прогретый повтор | 17.0 | 317 | 24/24 |
| Тот же формат, Qwen 3 4B | 28.2 | 389 | 21/24 |
| Тот же формат, Qwen 2.5 3B | 14.7 | 236 | 10/24 |

«Модель выгружена» означает явный unload из Ollama перед прогоном; файловый кеш ОС не очищался. Прогретый результат использовал кеш префикса: обработка первого входа заняла 0,10 с вместо 5,64 с. Поэтому 17 секунд нельзя считать обещанием для любого нового диалога. На запуске после unload: загрузка 2,60 с, обработка входов обоих проходов 8,20 с, генерация 14,01 с; общий вызов 25,08 с. Старый формат: обработка входа 3,03 с, генерация 187,63 с, затем лимит 4096 токенов оборвал ответ.

Все сравниваемые финальные компактные варианты: одна версия prompt outpatient.spans.zh.v5, один дополнительный PLAN_PROMPT, temperature=0, seed=42, think=false, контекст 16384, максимум 4096 выходных токенов на проход, retries=0. Старая генерация — отдельный baseline с полным JSON. Для диагностики таймаут попытки увеличен до 240 с; старый рабочий таймаут 180 с прервал бы этот пример раньше.

Ранние гипотезы: единый список выборов дал 10,5 с, но пропускал факты; обязательные девять разделов уменьшили пропуски. Уменьшение контекста до 8192 не дало убедительного выигрыша и сопровождалось пропусками. Qwen 2.5 7B с промежуточным prompt дала 17,7 с, но потеряла существенные сведения. Позиционная классификация всех 71 фрагментов дала неверные категории и не включена в рабочий код. Эти прогоны имеют разные промежуточные инструкции и не являются контролируемым сравнением моделей.

## Что проверяется

24 ручных критерия в benchmark.py: сохранность ключевых симптомов, доз/неизвестных доз, осмотра, предварительного диагноза, плана/отказа от инфузии, опасных симптомов и повторного визита; конфликт аллергии; отсутствие переноса астмы родственника пациенту; просьба пациента об азитромицине не превращена в текущее лечение. Это выборочные проверки одного development-примера. Prompt уточнялся по этому примеру; цифры не являются оценкой качества на независимом удержанном тесте или медицинской валидацией.

JSON Schema ограничивает номера фрагментов и роли; Pydantic повторно проверяет исходные цитаты и отсутствие ложного подтверждения. Полные text, evidence, reported_by, origin и reviewed собирает бэкенд. Один фрагмент может содержать несколько связанных фактов и смешанные положительные/отрицательные сведения: исходная фраза сохраняется целиком, но атомарная медицинская разметка не гарантируется.

Второй проход выполняет та же модель и не заменяет врача. Его факты объединяются с первым: исходные факты не удаляются, обнаруженный конфликт не снимается; разные статусы одной цитаты делают plan конфликтным. До полного успеха обоих проходов запись не сохраняется. Конфликты блокируют подтверждение. Все поля и роли по-прежнему проверяет врач.

## Повторение

```bash
.venv/bin/python experiments/03_outpatient_latency/benchmark.py --format full --name baseline-repeat
.venv/bin/python experiments/03_outpatient_latency/benchmark.py --plan-audit --name compact-repeat
.venv/bin/python experiments/03_outpatient_latency/benchmark.py --plan-audit --model qwen3:4b-instruct --name alternative-repeat
```

Все сырые ответы и длительности сохранены в [папке эксперимента](../experiments/03_outpatient_latency/). Не запускать CLI одновременно с использованием модели в интерфейсе: CLI имеет собственную блокировку процесса.

## Проверка продукта

Реальная браузерная проверка длинного примера: 25,9 с до заполнения девяти разделов, 24/24 критериев, ошибок браузера нет. Аллергия остаётся конфликтной; неподтверждённый экспорт скрыт. Это автоматизированная проверка, не проверка врачом.

Короткий пример из 9 реплик через интерфейс на финальном коде: 8.5 с вместо ранее измеренных 75–89 с; генерация, автоматизированные отметки проверки, JSON и печатная форма/PDF прошли. Автоматизированное подтверждение относится только к синтетическому демонстрационному случаю.

Проверки кода: 128 тестов, Ruff и сборка фронтенда прошли.

Повтор длинного примера через сайт после финального объединения проходов: 14.5 с на модель, 14,9 с до заполнения интерфейса, 24/24 критериев. Это прогретый повтор, а не SLA.
