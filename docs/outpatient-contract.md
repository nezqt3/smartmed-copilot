# Работающий контракт outpatient.v1

Версия реализована для обычного амбулаторного текстового сценария. Основания и сопоставление китайским разделам: [проект структуры](chinese-outpatient-contract-proposal.md). Это формат SmartMed, не готовый интерфейс HIS и не реализация всего WS 445.2.

## Сценарий

Вход сотрудника → проверка текста и ролей → генерация → правки → сохранение → проверка каждого раздела и данных приёма → подтверждение конкретной версии → печать/сохранение PDF или JSON.

Все новые маршруты требуют Bearer-токен существующего /v1/auth/login. Чтение черновиков общее для сотрудников этого локального демонстрационного экземпляра. Автор ручной правки, проверки реплик и подтверждения берётся из сессии. Клиент не назначает автора или дату подписи. Это подтверждение учётной записью, не квалифицированная электронная подпись.

```text
GET    /v1/outpatient/form
POST   /v1/outpatient/drafts
GET    /v1/outpatient/drafts/{id}
PUT    /v1/outpatient/drafts/{id}
POST   /v1/outpatient/drafts/{id}/confirm
GET    /v1/outpatient/drafts/{id}/export
GET    /v1/outpatient/drafts/{id}/print
GET    /v1/outpatient/drafts/{id}/history
DELETE /v1/outpatient/drafts/{id}?expected_version=N
```

## Генерация

```json
{
  "transcript_reviewed": true,
  "patient": {"patient_id": "demo-1", "name": "演示患者", "sex": "unknown", "age": null},
  "encounter": {"department": "全科门诊", "visit_type": "initial", "visited_at": null},
  "turns": [
    {"turn_id": 1, "speaker": "patient", "text": "我咳嗽两天了，没有发热。"},
    {"turn_id": 2, "speaker": "doctor", "text": "咽部充血。初步考虑上呼吸道感染。建议休息。"}
  ]
}
```

`transcript_reviewed` обязательно true. Реплики имеют уникальные turn_id и роли patient/doctor/third_party. Клиент не должен отправлять нераспределённых говорящих или считать speaker_0 автоматически врачом. Лимит — 8000 символов и 160 реплик. ASR должен отдать распознанные реплики/времена/ID говорящих; врач подтверждает роли и исходный текст перед этим запросом. Внутри нового контракта нет неявной миграции старого текста или определения ролей.

Данные пациента и приёма не отправляются LLM: модель получает только turns. Новая генерация — синхронный POST, не старая очередь /v1/jobs. Она делит блокировку модели с шестиполевым извлечением, при занятости возвращает 503 model_busy. Новое извлечение использует весь ограниченный диалог за один проход; сегментное объединение старого контракта не переносилось. Запрос, не поместившийся в контекст/выход или время, не создаёт частичный черновик. Лимит выдачи — 4096 токенов; число попыток задаётся repair_attempts. Таймаут одной попытки — outpatient_timeout_s (180 секунд по умолчанию, до 600); общий предел учитывает число попыток. Длинные и реальные диалоги требуют отдельной оценки.

Instructor отправляет в Ollama JSON Schema, системную инструкцию outpatient.zh.v4 и текст диалога. Цитаты ограничиваются исходными фрагментами; Pydantic проверяет роли и буквальное совпадение. Повторная попытка получает ошибки валидации. Модель не может выставить manual или reviewed=true. Структурная и буквальная проверка не доказывает медицинскую/смысловую корректность.

## Документ

Девять обязательных ключей: chief_complaint, present_illness, past_history, allergy_history, medication_history, physical_examination, investigations, assessment, plan.

Каждый раздел имеет status (documented/unknown/conflict), items и reviewed. До 24 элементов в разделе; по 2000 символов текста в элементе. Unknown имеет пустой список и не означает отрицание. Conflict имеет цитаты спорных сведений и блокирует подтверждение до разрешения врачом.

```json
{
  "status": "documented",
  "reviewed": false,
  "items": [{
    "text": "初步考虑上呼吸道感染",
    "assertion": "uncertain",
    "origin": "transcript",
    "reported_by": "doctor",
    "evidence": [{"turn_id": 2, "quote": "初步考虑上呼吸道感染。"}],
    "reviewed": false
  }]
}
```

История/жалобы/аллергии/уже принятые лекарства: patient или third_party. Осмотр, оценка и план: doctor. Исследования: любая из трёх ролей с сохранением источника. Слова родственника должны относиться к пациенту; проверка смысла требует человека. Литературный пересказ моделью пока не разрешён: text копируется из цитаты, чтобы не терять смысл/источник.

Для явных китайских маркеров предварительного диагноза (可能/考虑/怀疑/疑似/尚未确诊/待排) требуется uncertain. Вопросы врача в осмотре/оценке/плане отклоняются узкой эвристикой. Это не универсальный семантический классификатор.

Ручной ввод/правка: origin=manual, reported_by=clinician, evidence=[]. Не подделывать цитату. В истории сохраняется автор всей правки и версия документа. При сохранении сервер сбрасывает все отметки проверки и окончательное подтверждение.

## Сохранение и подтверждение

PUT принимает expected_version, patient, encounter и document. Ответ содержит новую версию. Устаревшая версия — 409. Реплики после генерации неизменны; исправленный исходный диалог требует новой генерации.

POST confirm принимает:

```json
{
  "expected_version": 1,
  "reviewed": true,
  "reviewed_sections": ["chief_complaint", "present_illness", "past_history", "allergy_history", "medication_history", "physical_examination", "investigations", "assessment", "plan"],
  "patient_encounter_reviewed": true
}
```

Панель требует отдельные отметки всех разделов и данных пациента/приёма; сервер требует полный перечень разделов и явное подтверждение. Unknown можно подтвердить как неизвестное; пустые поля не заполняются догадками. Это заявление пользователя о проверке, а не независимое доказательство присутствия врача.

## Экспорт и хранение

Кнопка «复制病历正文» копирует читаемый текст подтверждённой серверной версии для ручной вставки в онлайн-систему. Это не автоматическая HIS-интеграция.

JSON включает документ, источники, пациента/приём, исходные turns, метаданные модели, подтверждающего сотрудника, время и версию. Печатный HTML содержит те же сохранённые клинические разделы и регистрационные сведения; пользователь может выбрать «Сохранить PDF» в браузере. Доступ только после подтверждения, при правках подтверждение снимается. HTML экранируется; неподтверждённый экспорт — 409.

Новые записи и ревизии используют отдельные таблицы outpatient_drafts/outpatient_revisions в существующей SQLite. extraction.v1/v2 и старые API сохранены, они не объявляются полноценными амбулаторными записями. У новых записей применяется retention_days при обращениях к новым маршрутам: просроченные записи и ревизии удаляются; отдельного фонового таймера для этих таблиц пока нет. DELETE удаляет запись и ревизии при совпадении версии.

## Что осталось

Запись с микрофона, рабочий ASR/диаризация и предложение ролей — Денис. Коды диагнозов из справочника пока не выбираются в новой панели; врач может вписать название вручную. Полноценная структура рецепта, цифровая подпись и HIS-интеграция не подключены. Правила лекарственной безопасности старого шестиполевого API не следует считать валидированным анализом нового plan. Перед реальным применением нужны независимая разметка/врачебная проверка и оценка нового набора.

Для компактности используется общая схема цитат исходного диалога; допустимые роли каждого раздела проверяет Pydantic. Единственная нормализация: точная копия факта врача в истории удаляется, если полностью идентичный элемент уже сохранён в допустимом разделе врача. Это не перенос, не пересказ и не выбор новой медицинской интерпретации; исходные цитаты сохраняются, событие записывается в метаданные. Несовпадающие/неподтверждённые элементы не удаляются и должны пройти обычную проверку.
