# Проверка outpatient.v1 — 11 октября 2026

Выполнены саморевью, проверка API и настоящей локальной модели. Коммит объединяет ранее не опубликованные изменения Павла (авторизация, очередь, версии, безопасность, корпус 03) с новой амбулаторной записью и фронтом Дениса.

## Результаты

- 114 тестов прошли: tests + experiments/02_model_comparison/test_scoring.py + experiments/01_baseline/test_checks.py. Одно предупреждение о старом httpx-интерфейсе Starlette.
- Ruff src/tests/services/asr/app.py, npm run build и git diff --check прошли.
- Корпус 03: 40 примеров, 10 API-проверок прошли; человеческая разметка не завершена.
- Playwright: вход → проверка реплик/ролей → настоящий вызов Qwen → отметки всех разделов и данных приёма → подтверждение → скачивание JSON → серверная печать и создание PDF. Копирование подтверждённого текста для онлайн-системы проверено отдельно.
- Настоящая модель qwen3.5:4b, prompt outpatient.zh.v4, think=false, temperature=0, seed=42. Успешная генерация одного синтетического диалога заняла 75.001 секунды; это не средняя задержка и не оценка качества на корпусе.
- Результат: несколько жалоб и отрицание температуры; сообщённый гипертонический анамнез; неизвестная аллергия; уже принятый ибупрофен 200 мг; измеренная врачом температура и находка; предварительная оценка сохранена как uncertain; рекомендации и повторный приём отдельно в плане.

## Ошибки, обнаруженные и исправленные

Первый успешный структурный ответ неправильно поместил слова врача в историю болезни и потерял статус предварительного диагноза. Добавлены проверки источников разделов, маркеров неопределённости и вопросов врача. История требует источника patient/third_party, осмотр/оценка/план — doctor; ручные правки имеют отдельное происхождение.

У модели сохранилась склонность дублировать находку врача в истории. В успешном ответе удалён один полностью идентичный дубль «咽部充血» из истории: оригинал с тем же текстом, статусом, источником и цитатой сохранён в осмотре. Эта узкая нормализация записана в метаданные; она не угадывает медицинский смысл и не удаляет отличающиеся факты. На неверные источники и несовпадающие дубли есть тесты.

Большие развёрнутые схемы с повторяющимися ограничениями приводили к таймаутам. Финальная схема компактная; разделы проверяются Pydantic, цитаты ограничены оригинальными фрагментами. Таймаут outpatient_timeout_s отделён от старого извлечения и составляет 180 секунд на попытку по умолчанию. Неудачная или обрезанная генерация не создаёт черновик.

Также исправлены три дефекта предыдущего ревью Дениса: неоднозначный короткий ответ об аллергии, усечённый WAV и JSON не-объект от ASR. Все получили регрессионные тесты.

## Границы проверки

Подтверждение тестового черновика выполнено автоматизированным браузером под demo_frontend: это тест переходов состояний, не проверка врачом. Клиническая оценка и независимая человеческая разметка нового контракта не проводились. Проверки схемы, роли и цитаты не гарантируют правильной медицинской интерпретации.

В outpatient.v1 извлечение текста дословное; литературный пересказ, полноценный рецепт, анализ взаимодействий, врачебная электронная подпись и HIS-интеграция не реализованы. Аудиозапись/ASR/автоматические роли ожидают подключения Дениса. Работа нового контракта на длинных и реальных диалогах не подтверждена. До 24 фактов в разделе, 8000 символов входа и 4096 токенов выхода; слишком большой запрос должен завершаться ошибкой, не частичной записью.

Протестирован контракт SmartMed для обычного амбулаторного приёма; он не заявляется как готовая реализация национального стандарта или шаблона конкретной больницы.

Для Дениса: docs/outpatient-contract.md и examples/outpatient_encounter_zh.json. Бэкенд принимает проверенные текстовые реплики; speaker_id из диаризации сначала связывается с подтверждённой врачом ролью. Исходные реплики после генерации неизменны; их исправление требует новой генерации.
