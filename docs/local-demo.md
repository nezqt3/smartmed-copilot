# Локальное демо SmartMed

## Запуск

На Mac `start-demo.sh` использует нативную Ollama (Metal/GPU), локальный API из `.venv`
и панель на http://127.0.0.1:5173. Установи Ollama, запусти её приложение,
создай `.venv` и установи проект (`.venv/bin/pip install -e ".[dev]"`).
Docker запускает только ASR (один CPU, порт 18001) и справочник (порт 18002); контейнерная Ollama останавливается.
Локальные учётные записи и черновики находятся в `data/`; Docker volumes используются
для весов ASR. Ctrl+C завершает API и панель. На Linux панель остаётся на порту 8080.

Нужен запущенный Docker Desktop и примерно 8 ГБ свободного места при первом скачивании моделей и образов. Из корня проекта:

```sh
sh tools/start-demo.sh
```

При первом запуске скрипт попросит задать пароль сотрудника `demo_frontend` (минимум 12 символов). Открой <http://127.0.0.1:8080> и войди. На Linux модели и данные сохраняются в Docker volumes; повторный запуск не требует новой загрузки.

Интерфейс по умолчанию на русском. В хэдере можно выбрать English или 中文; выбор сохраняется в браузере. Диалог, извлечённые медицинские данные и печатная форма автоматически не переводятся.

## Показ за несколько минут

1. Заполни синтетические данные пациента или оставь неизвестные поля пустыми.
   Время приёма заполняется автоматически, ID врача берётся из входа. Дополнительные данные раскрываются по нажатию «Пациент и приём»; последнее отделение запоминается на этом устройстве.
2. Для быстрого показа нажми **Загрузить пример**. Для голосового показа нажми **Начать запись**, разреши браузеру доступ к микрофону, запиши разговор на китайском и нажми **Остановить и распознать**. На `127.0.0.1` разрешён доступ к микрофону. Есть и загрузка WAV.
3. После ASR локальная модель сама предложит границы реплик и роли врача, пациента или третьего лица. Быстро проверь результат; сомнительные реплики будут отмечены. При ошибке можно поправить роль и текст прямо в редакторе. Чтобы разделить слитую реплику, поставь курсор внутри её текста и нажми «Разделить в месте курсора». Правая часть получит противоположную роль и будет отмечена для проверки. Если модель не смогла разметить текст, исходная расшифровка останется для повторной попытки.
4. Отметь **Я проверил текст и роль каждой реплики**, затем нажми **Создать медкарту**.
5. Проверь девять разделов и их цитаты. При необходимости исправь текст и нажми **Сохранить правки**. Отметь проверку каждого раздела и данных пациента, затем нажми **Подтвердить медкарту**.
6. Покажи **Скачать JSON (для интеграции)** и **Печать / сохранить PDF**. Печать открывает браузерное окно, где выбирается сохранение PDF.

Для проверки ASR без микрофона есть синтетический файл `experiments/04_audio_corpus/clips/audio_dev_01.wav`. Его транскрипция может содержать ошибки, которые нужно исправить перед генерацией.

На проверенном Mac генерация девяти разделов из короткого девятирепликового примера в Docker заняла 119 секунд; первый проход ASR по длинному синтетическому WAV занял около 76 секунд. На живом показе подготовь пример заранее и дождись завершения индикатора обработки.

## Быстрая диагностика

```sh
docker compose ps
curl http://127.0.0.1:8000/health
docker compose logs --tail=50 api asr ollama
```

Если пароль сотрудника забыт, можно задать новый (старые сессии сотрудника сбросятся):

```sh
docker compose exec api python -m smartmed.auth demo_frontend --database /app/data/staff.sqlite3
```

Для остановки: `docker compose down`. Не добавляй `-v`, если хочешь сохранить модели, учётные записи и локальные черновики.

Это демонстрационный сценарий на синтетических данных. Разделение ролей делается по смыслу текста, без анализа голосов, поэтому короткие и неоднозначные фразы модель может приписать не тому человеку. Медицинская правильность, качество ASR и ролей на реальных приёмах не валидированы; HIS-интеграции нет.

Разбиение ASR принимает до 8000 символов и обрабатывает их последовательно порциями
до 400 символов без потери текста. Стык порций отмечается для проверки роли.
`SMARTMED_BACKEND_CPU_THREADS` ограничивает потоки Ollama (по умолчанию 2);
в Docker дополнительно ограничены CPU Ollama (2) и ASR (1).

Проверка production-маршрутов с нативной Ollama на синтетическом тексте:

```sh
SMARTMED_BACKEND_CONTEXT_TOKENS=8192 SMARTMED_BACKEND_ASR_URL=http://127.0.0.1:18001 \
  .venv/bin/python tools/pipeline_smoke.py
```

Для сквозной проверки WAV → ASR → роли → черновик добавь
`--audio experiments/04_audio_corpus/clips/audio_dev_01.wav`. Скрипт использует
временную базу и удаляет тестовый черновик и сотрудника при завершении.
Успех проверки означает прохождение API и проверки структуры/цитат,
а медицинский смысл и правильность ролей требуют отдельной проверки.

Если модель не дала надёжных границ порции, исходный блок сохраняется с
`manual_required` и отметкой неопределённой роли. Панель просит разделить этот
блок и проверить роли вручную; автоматического повторного запуска модели нет.
