# Синтетический аудионабор

`scripts.json` содержит шесть придуманных китайских диалогов: три `dev` и три `test`. `clips/` содержит моно PCM16 WAV 16 кГц; `manifest.json` фиксирует длительность, SHA-256, роли, тексты и способ создания. В каждом клипе реплики врача и пациента произнесены разными голосами macOS и разделены паузами. Это TTS, не запись реального приёма и не проверка в клиническом шуме. Тексты взяты из сценариев, независимая ручная транскрипция и проверка носителем китайского языка пока не выполнялись.

Клипы предназначены для локальной разработки. Права на публичное распространение синтезированных голосов отдельно не проверялись; перед публикацией корпуса их нужно уточнить или заменить аудио на материал с подтверждёнными правами.

Проверка файлов: `python3 experiments/04_audio_corpus/validate.py`. Повторная генерация на Mac с `say` и `ffmpeg`: `python3 experiments/04_audio_corpus/build.py`. Разные версии голосов могут изменить WAV и контрольные суммы. Сохранённые WAV подходят для контейнера и Linux без повторной генерации.

ASR возвращает сплошной текст без надёжных границ реплик. Перед вызовом `POST /v1/drafts` человек сверяет текст с аудио, исправляет ошибки и вручную указывает `doctor`/`patient` для каждой реплики. Нельзя использовать сценарий как эталон реальной акустической точности: TTS читает именно его.

После запуска API выполните `python3 experiments/04_audio_corpus/evaluate.py` или `docker compose run --rm audio-eval`. Скрипт сохранит текст ASR, время и CER по каждому клипу в `results/asr.json`. Эталон здесь — исходный сценарий синтеза, а не независимая ручная транскрипция; CER характеризует только этот TTS-набор.
