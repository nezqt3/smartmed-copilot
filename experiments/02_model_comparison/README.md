# Сравнение локальных Qwen для SmartMed

Задача — извлечь шесть полей из китайского диалога с цитатами пациента. Это проверка компонента прототипа, не проверка медицинских диагнозов и не клинический бенчмарк.

## Кандидаты

- `qwen2.5:3b` — компактная исходная модель.
- `qwen2.5:7b` — проверка эффекта увеличения размера в том же семействе.
- `qwen3:4b-instruct` — компактная версия без рассуждений.
- `qwen3.5:4b` — более новое семейство, запрос с `think=false`.

Запросы идут только на `127.0.0.1:11434`. Интернет нужен для скачивания весов; диалоги в облачные API не отправляются.

## Что именно измеряем

В `cases_test.json` 40 синтетических примеров, составленных AI-ассистентом. Русские пояснения и эталоны остаются в оценочном скрипте, модель получает только китайские реплики. Эталоны зафиксированы до первого прогона расширенного набора. Проверена их структура и буквальное наличие цитат; китайский носителем языка и врачом не проверен.

Категории: отрицания, неизвестные сведения, аллергии, дозы и единицы, слова врача, планируемый приём, сведения о родственниках, исправления пациента, команды внутри диалога, отвлекающие числа и длинные диалоги. Внутри категорий есть сходные примеры: 40 случаев нельзя считать 40 независимыми клиническими наблюдениями.

Этот набор используется для **выбора модели**. Название `test` означает проверочные примеры в скрипте; это не независимый финальный тест после выбора модели. Для конкурсных заявлений о качестве нужны отдельные реалистичные данные, проверенные человеком, и закрытая итоговая выборка.

- **Status accuracy:** доля полей с правильным `present / negated / unknown`.
- **Macro F1:** средний F1 по трём статусам, чтобы множество неизвестных полей не скрывало ошибки на положительных фактах.
- **Unsupported positives:** модель указала наличие факта, которого нет в эталоне. Это операционная метрика, не клиническая частота галлюцинаций.
- **Missed positives:** модель потеряла положительный факт.
- **Valid cases:** ответ прошёл структуру, обязательные значения и проверку буквальных цитат пациента. Эта проверка не доказывает соответствие цитаты смыслу поля.
- **Exact status+value:** строгое совпадение текста значения. Отличие границ фразы может быть формальным; эти случаи нужно разбирать вручную.

Все модели получают одинаковые prompt/schema, контекст 4096 токенов, лимит ответа 1400, temperature=0, seed=42, отключённые рассуждения. Хэши набора, инструкции, скрипта и идентификаторы моделей записываются в результаты. Никакого дообучения в этом сравнении нет.

Первые прогоны качества могут идти одновременно со скачиванием весов. Их время не используется для ранжирования скорости. После завершения скачиваний отдельный прогон измеряет пять одинаковых случаев, повторённых трижды. Первый запрос отдельно отмечается как запуск после выгрузки модели, следующие 14 — работа загруженной модели. P95 на 14 запросах — предварительная оценка, не гарантия задержки. Скорость ASR и всего приложения сюда не входит.

Размер загруженной модели из Ollama — сообщённый движком объём выделения, **не измеренный пик RAM**. Пользовательские программы и тепловой режим Mac также влияют на скорость.

## Как запускать

Из корня репозитория:

```sh
python3 experiments/02_model_comparison/build_cases.py
python3 experiments/02_model_comparison/compare_models.py
```

Сначала модели должны быть скачаны через `ollama pull`. Скрипт ждёт появления всех четырёх моделей до двух часов, запускает их последовательно, выгружает между моделями и сохраняет промежуточные результаты. Повторное построение набора после начала оценки не нужно.

Путь к текущему отчёту находится в `LATEST_RESULT.txt`. В папке результатов есть исходные ответы, ошибки по каждому полю, `summary.json` и `REPORT.md`. Поле `complete` подтверждает завершение всей программы; промежуточная таблица не означает окончательный выбор.

Выбираем модель сначала по смысловым ошибкам и доказательствам, затем по задержке и расходу ресурсов. Если ни один кандидат не проходит нужные случаи, это вывод о необходимости доработать извлечение, а не повод объявить победителем самый быстрый.
