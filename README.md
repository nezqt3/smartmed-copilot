# SmartMed Ambient EHR Copilot

Агент амбиентного документирования амбулаторного приёма: стенограмма диалога -> структурированная
запись по SOAP с кодом МКБ-10 (национальная клиническая ревизия 2.0) -> детерминированная проверка
назначения -> черновик на подтверждение врачу. Система не подписывает документ.

Предложения: `docs/` (RU / EN / ZH версии одной записки).

## Установка

```
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pytest
```

## Рабочий локальный API

Бэкенд под Qwen3.5:4b: извлечение шести фактов, Instructor/Pydantic, проверка цитат,
SQLite, редактирование с версиями, подтверждение и экспорт JSON.
[Запуск и объяснение кода](docs/BACKEND_START_HERE.md).
[Разбор реальных ошибок модели](docs/MODEL_FAILURES_RU.md).
[Контракт для Дена: запись, форма и все ручки](docs/DEN_FRONTEND_API.md).

```sh
.venv/bin/uvicorn smartmed.api:create_app --factory --host 127.0.0.1 --port 8000
```

После запуска: http://127.0.0.1:8000/docs. Контракт для фронтенда: `GET /v1/form`.
Полный SOAP, ASR, ICD и проверка назначений остаются следующим этапом.

## Структура

```
src/smartmed/schemas    модель записи приёма и JSON-схема для ограниченного декодирования
src/smartmed/config     настройки контура: путь модели, бюджеты задержки, пороги отказа
src/smartmed/api.py     рабочий FastAPI: черновики, правки, подтверждение, журнал
src/smartmed/model_client.py  Instructor + локальный Ollama, ограниченные повторы
src/smartmed/store.py   SQLite и версии черновиков
apps/panel              планируемая панель проверки врача (ещё не реализована)
configs/rules           планируемые пакеты правил безопасности
data                    корпус, чекпоинты, удержанная выборка (вне git)
scripts                 прогоны оценки, генерация синтетики, замеры задержки
```

## Контракт схемы

`smartmed.schemas.strict_json_schema()` отдаёт Draft 2020-12 без `$ref`, с
`additionalProperties: false` и полным списком `required`, поэтому декодирование ограничивается
грамматикой. Вывод всё равно нужно проверять на полноту и корректность. Необязательные поля nullable: поле, которое
стенограмма не подтверждает, приходит как `null`, а `abstained_fields` перечисляет те из них, что
остались на ручной ввод врача. Каждое заполненное поле обязано иметь основание в `citations` (путь
поля + id фрагментов стенограммы); `EncounterRecord.uncited_populated_fields()` находит нарушения до
постановки черновика в очередь.
