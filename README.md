# SmartMed Ambient EHR Copilot

> Новая панель: **outpatient.v1**, девять разделов китайской амбулаторной записи,
> несколько фактов в разделе, источники, ручные правки, проверка врачом и печать/сохранение PDF.
> Запуск: API как ниже, `cd apps/panel && npm ci && npm run dev`; http://127.0.0.1:5173.
> Компактная генерация включена; на синтетическом диалоге из 32 реплик — 17–25 секунд.
> [Замеры и ограничения](docs/outpatient-latency-2026-10-11.md).
> [Актуальный контракт](docs/outpatient-contract.md). Старый шестиполевый сценарий описан ниже
> и доступен через переключатель панели. ASR и роли ещё требуют подключения.


**Русский** | [English](README.en.md) | [中文](README.zh-CN.md)

Локальный текстовый прототип подготовки китайской амбулаторной записи:
диалог → шесть фактов с цитатами пациента → черновик → ручная проверка → экспорт JSON.
Проверки структуры и цитат не гарантируют медицинскую правильность. Данные для оценки синтетические;
проверка врачом и клиническая валидация не проводились. Название Ambient описывает цель проекта:
интерфейс, локальное ASR, полный SOAP и диагнозы ещё требуют интеграции.

## Установка и запуск

Python 3.11+, macOS или Linux, установленная и запущенная Ollama. Веса скачиваются отдельно,
внешний API-ключ не нужен. Создание сотрудника запрашивает пароль скрыто (не менее 12 символов).

```sh
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
ollama pull qwen3.5:4b
.venv/bin/python -m smartmed.auth pavel
.venv/bin/uvicorn smartmed.api:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

Один процесс API на базу: очередь последовательно использует одну локальную модель.
Повторный запуск с той же базой блокируется файловой блокировкой.
Открой [Swagger](http://127.0.0.1:8000/docs): выполни login с `staff_id` и `passcode`,
скопируй `access_token` в Authorize. Токен действует час; logout аннулирует его.
После пяти попыток входа без успешного входа ID блокируется на 15 минут.

## API и подключение интерфейса

```text
POST   /v1/auth/login
POST   /v1/auth/logout
GET    /health
GET    /v1/form
GET    /v1/medications?q=布洛芬
POST   /v1/jobs                         → 202 + job_id
GET    /v1/jobs/{job_id}
DELETE /v1/jobs/{job_id}
POST   /v1/drafts                       → 201 (blocking compatibility route)
GET    /v1/drafts/{id}
PUT    /v1/drafts/{id}
GET    /v1/drafts/{id}/safety
POST   /v1/drafts/{id}/confirm
GET    /v1/drafts/{id}/history
GET    /v1/drafts/{id}/export
DELETE /v1/drafts/{id}?expected_version=N
```

Рекомендуемый сценарий интерфейса: `POST /v1/jobs` → опрос статуса раз в секунду →
при `succeeded` загрузить черновик по `draft_id`. Статусы: `queued`, `running`, `succeeded`, `failed`.
При `failed` показывать код ошибки, не подтверждать и не экспортировать запись.
Вместимость очереди — 8 заданий, включая выполняемое; переполнение возвращает 503 и Retry-After.
Задания сохраняются в SQLite: ожидающие продолжаются после перезапуска, прерванные выполняемые
получают `server_restart` без повторного запуска. Удалить выполняемое задание нельзя (409);
удаление завершённого задания не удаляет сам черновик.

Все маршруты черновиков, очереди и справочника требуют `Authorization: Bearer <token>`.
Автор правки и подтверждения определяется токеном; необязательные `actor`/`reviewer` должны совпадать.
Сотрудники этого локального прототипа работают с общей базой черновиков, а статусы заданий видит
только их создатель. Пароли хранятся отдельно (PBKDF2-SHA256, случайная соль); сохраняются хэши токенов.

Правка принимает `expected_version` и `document`; конфликт версии возвращает 409.
Перед подтверждением запроси `/safety`. Подтверждение принимает `expected_version`, `reviewed: true`
и список `acknowledged_alerts`. Обязательные предупреждения без подтверждения возвращают 409
`safety_acknowledgement_required`. Любая правка сбрасывает подтверждение и список подтверждённых
предупреждений. Экспорт разрешён только после проверки; это экспорт записи об уже сообщённых фактах,
а не разрешение назначать лечение. Полный пример: [контракт для Дениса](docs/backend-contract.md).

CORS допускает один локальный origin `http://127.0.0.1:5173`.
Настройка `SMARTMED_BACKEND_FRONTEND_ORIGIN` позволяет указать другой loopback origin.
Swagger и `GET /openapi.json` содержат актуальные схемы.

## Извлечение, длинные диалоги и версии

Шесть полей:发热, 咳嗽, 症状持续时间, 青霉素过敏, 已用药物, 已用药物剂量.
Статусы: `present`, `negated`, `unknown`; неизвестное не считается отрицанием.
Роли: `patient`, `doctor`, `third_party`; цитаты врача и родственника нельзя использовать как факты пациента.
Текст диалога остаётся данными, команды внутри него не меняют инструкцию модели.

Предел — 8000 символов и 160 реплик. До передачи модели текст делится по предложениям на сегменты
до 1800 символов. Одно предложение длиннее 1800 отклоняется с 422 без обрезки.
Разбиение сохраняет все исходные символы и ID реплик; цитаты повторно проверяются по полному диалогу.
Неизвестное в другом сегменте не затирает факт. Противоречащие статусы или разные значения
дают `unknown` и предупреждение, требующее ручной проверки. Это консервативный merge,
он не гарантирует разрешения исправлений и анафор между сегментами.

Ollama работает только по loopback, с `think=false`, temperature=0, seed=42, контекстом 16384.
Модель выбирает цитаты из исходных фрагментов схемы; Instructor/Pydantic проверяют результат.
Digest модели, версия и хэш prompt, параметры и сегменты записываются в метаданные.
Контекст, завершение генерации и таймаут проверяются; сбой одного сегмента не создаёт частичного черновика.

`extraction.v2` добавляет роль третьего лица и подтверждение предупреждений.
При чтении черновиков и ревизий применяется конкретная миграция v1 → v2 без изменения медицинских фактов;
при следующей записи ставится v2. Неизвестная или повреждённая версия даёт 409 `stored_contract_invalid`.

Regex кашля `咳|咯` — узкая эвристика на синтетической выборке; `一直干咳` проходит её.
Для реальных диалогов правило нужно отдельно оценивать и расширять. Явные отрицания аллергии и
принятых лекарств проверяются жёстко: отсутствие опыта приёма пенициллина не доказывает отсутствия аллергии.

## Правила безопасности и справочник

Офлайн-индекс содержит 5 ингредиентов: амоксициллин, бензилпенициллин, ибупрофен, парацетамол,
цефалексин. Для названия и ATC приложены ссылки WHO ATC/DDD; китайские алиасы составлены вручную.
Это демонстрационный индекс, не китайский реестр зарегистрированных препаратов.
Он не предлагает дозы, диагнозы, замену препарата или полный анализ взаимодействий.

Предупреждения охватывают неизвестную аллергию, лекарство вне индекса, неизвестную дозу,
дозу без лекарства, сообщённый приём пенициллинового препарата при не исключённой аллергии и
конфликты сегментов. Обязательные предупреждения врач подтверждает явно;
никакое предупреждение не меняет исходный факт автоматически. [Правила и источники](docs/safety-and-medications.md).

## Хранение и удаление

Базы `data/smartmed.sqlite3` и `data/staff.sqlite3` создаются с правами 0600.
Срок хранения демонстрационных черновиков — 7 дней от создания; уборка при старте и затем каждый час.
Настройка `SMARTMED_BACKEND_RETENTION_DAYS` изменяет срок (1–365 дней).
Удаляются черновик, все ревизии и связанный статус задания. Завершённые статусы заданий живут час;
текст задания очищается сразу после успеха или ошибки. SQLite secure_delete включён.

Резервные копии, журналы экспериментальных прогонов, экспортированные JSON и аудио вне бэкенда
нужно удалять отдельно. Экспериментальные файлы содержат только синтетические данные и исключены из Git.
Это не гарантия физического стирания носителя и не подтверждение правового соответствия.
Реальные данные требуют согласованного режима хранения, доступа и проверки системы.

## Проверки и измеренные результаты

```sh
.venv/bin/ruff check src tests experiments/03_backend_smoke/run.py experiments/04_api_walkthrough/run.py experiments/05_backend_evaluation
.venv/bin/pytest tests experiments/02_model_comparison/test_scoring.py experiments/01_baseline/test_checks.py
.venv/bin/python experiments/05_backend_evaluation/run.py --models qwen3.5:4b qwen2.5:3b
```

CI выполняет Ruff и тесты без Ollama. [Измеренные результаты](docs/backend-evaluation.md)
отдельно показывают старое сравнение четырёх моделей на 40 случаях и новый прогон production API.
Метрика исправлений — симуляция по эталону, не измерение работы врача.
Новый набор зафиксирован до первого прогона; он синтетический и не проверен человеком.
Для совместной проверки подготовлены [правила разметки](docs/annotation-guide.md).

Сквозной HTTP-сценарий с работающим API: `.venv/bin/python experiments/04_api_walkthrough/run.py`.
Он запрашивает логин скрыто, использует синтетический диалог и пишет результаты локально.
